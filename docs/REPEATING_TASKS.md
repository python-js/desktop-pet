# 重复待办设计与验收（0.5）

## 用户行为

新增/编辑待办和任务草稿均可选择：不重复、每天、每周一至五、每周。任务列表和提醒窗口显示重复规则。已完成记录保留原计划，完成本次后自动生成唯一的下一次未完成任务。

这是以完成为触发的重复待办：本次未完成时，不自动累积下一次，不会每天重新弹出已呈现的旧任务。若希望跳到下一次，请完成当前项。完全退出后重启，仍会补检当前未完成的逾期项。

聊天本地模式可识别：

- `每天15:00提醒我喝水`
- `每个工作日09:00提醒我看邮件`
- `每周五17:00提醒我交周报`

模型服务也可给出 repeat 字段建议，必须在草稿卡片核对并确认。没有给出该字段时默认为不重复；非法值被拒绝，不自行推测。

## 时间与延期

`due_at` 是本次实际提醒时间，按 UTC 存储。`scheduled_at` 是本次原计划，保留创建时的 UTC 偏移。延期十分钟只改 due_at，不改 scheduled_at。仅改标题、保留当前实际提醒时间时也不改变原计划；显式改提醒时间或重复规则时重设计划基准。

下次时间从原计划推导，同时严格晚于原计划及完成时刻；漏做多天会跳过过去日期，只生成一条未来任务。每天保持原时刻；每周保持原星期和时刻；周一至五跳过周六日，**不识别节假日和调休**。

当前使用固定 UTC 偏移，不能随夏令时自动调整或跟随旅行更换时区。跨时区/夏令时需手动检查并编辑任务。月度、年度、自定义间隔暂未支持。

## 一致性与撤销

完成采用事务：仅当任务仍为 pending 才改为 done、生成下一条并写 next_id。重复点击或同一记录再次完成不会重复生成。中途出错会回滚整个事务。

已经生成下一次的历史记录不能直接恢复为待办，以免同一系列出现两个未完成项；界面提示编辑下一次。删除当前未完成项即停止此系列继续生成；撤销删除会恢复该项及规则。将下一次改为“不重复”也可终止后续重复。

旧数据库升级到 schema 4：先备份，然后在事务中补充任务的 repeat_rule、scheduled_at、next_id，以及草稿 repeat_rule。旧任务默认不重复，原 due_at 填入 scheduled_at，不改变提醒时间。

## 列表筛选

未完成列表可选择全部、今天、未来日期、已逾期，与标题搜索组合。今天包括本地当天已逾期和未到点任务；未来日期从明天开始；逾期跨所有日期。已完成列表关闭时间筛选，保留标题搜索。列表每30秒更新，保留选中项与滚动位置。

## 验证

自动化覆盖：闰日、跨月、周五至周一、周重复、跳过多天、延期保留原时刻、仅编辑标题、完成去重、停止重复、旧 schema 3 升级、草稿确认、非法模型规则、午夜时区筛选。Qt 集成测试覆盖从草稿选择每天、确认、列表过滤和完成后出现下一条。

真实供应商对 repeat 字段的理解、跨时区系统变更和多日真实运行仍需人工联调。已有 Windows 单次提醒弹窗曾由用户确认，不等于本轮重复提醒已完成长时间运行验收。

## 对话默认规则（0.17.2）

未明确说重复时默认一次性提醒，不追问重复选项；明确每天、工作日或每周时直接填入对应规则。只说“重复”或“重复提醒”时按每天同一时间处理，并简要告知。用户说只提醒一次或不重复时使用none。仅在日期/时间确实不明确或频率超出现有能力时追问或说明。明确请求且事项和时间完整时，由程序直接保存、设置提醒并反馈结果，不再显示确认保存卡片。历史版本遗留草稿仍可手动处理，不自动提交旧草稿。相同标题、时间和重复规则的未完成待办不会重复创建。
