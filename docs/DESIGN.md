# Desktop Pet 产品与技术设计

版本：0.17；日期：2026-10-26；目标平台：Windows 10/11 x64，后续适配 macOS。

## 1. 产品目标与范围

把桌宠作为一个轻量的个人事务入口：用户可以随时聊天、把自然语言转为待办、确认提醒时间，并由桌宠在到点后提醒。

首版保留三个主要入口：聊天、待办、设置。桌宠窗口独立于主窗口；关闭主窗口时，在系统托盘可用的情况下继续运行。菜单中明确提供退出；完全退出或关机时不会提醒。Windows 首版不承诺睡眠唤醒、系统服务或手机推送。

### 首版功能

- OpenAI 格式兼容的 Chat Completions 服务接入；用户自行填写服务地址、模型名和 API Key。不预置付费模型或密钥。
- 多会话聊天历史保存在本地，支持新建、自动命名、手动重命名；网络请求在工作线程执行，界面保持响应。
- 无模型配置时可手工创建待办，也可识别有限的中文时间命令；不能把规则模式描述为真正的大模型。
- AI 回复使用受校验的 JSON 协议，最多给出 10 条待办建议。建议展示为草稿；用户检查标题和具体时间后逐条保存。
- 本地 SQLite 保存待办；支持完成、延期十分钟、修改标题和时间。
- 到期后弹出非模态提醒窗口、桌宠气泡和托盘通知（取决于系统设置）；窗口有完成、稍后提醒操作。
- 内置程序绘制的基础宠物；支持上传本地 PNG/JPG/WebP，复制到应用数据目录，使用基础浮动动画。图片不发送给模型。
- 宠物支持拖动、双击打开主窗口、右键菜单；不依赖外部角色版权素材。

### 后续功能

每日规划、任务分类与优先级、去背景、动画序列、Live2D 后端、3D、云同步、安装包、macOS 验证均分阶段实现。0.2 已增加失败请求重试、草稿恢复及任务历史；0.3 增加多会话及会话隔离；0.4 增加流式展示与协作停止；0.5 增加重复待办及时间筛选；0.6 增加可选安全密钥存储及登录启动代码，原生行为待验收。应用不开放任意代码执行或文件操作工具。

## 2. 用户流程与界面

### 聊天

默认打开聊天页，恢复上次选中的会话。顶部提供会话下拉、新对话和重命名；新对话的首条消息取前24字自动命名。每个会话分别持久化未发送文字、消息和任务草稿；切换时恢复。输入区随窗口伸缩，支持 Ctrl+Enter 发送。

发送时显示“正在回复”，全局一次只发一个请求，允许切换话题、浏览其他页面和编辑输入。工作线程请求绑定原始会话；切换后收到的回复与草稿写回原会话，不污染当前话题。失败重试入口按会话在内存中保存，切回可重试；重启后该入口不恢复。错误不把 API Key、原始响应或请求头写入日志。

AI 可回复文字和任务建议。文字显示为纯文本，避免把模型输出作为 HTML 执行。任务建议进入独立的草稿区域，每条显示标题、具体日期时间、编辑字段和保存按钮。缺失或含糊时间时模型应追问；客户端仍进行二次校验，不允许保存无效或过去时间。

### 待办

列表可切换未完成/已完成，按提醒时间排序并搜索标题；显示逾期状态。未完成任务可双击编辑，支持新增、完成、延期十分钟。历史任务可恢复为待办，若已过期将重新提醒。删除采用软删除，当前进程可撤销最近一次删除，恢复原完成状态；不提供永久清除。手动新增使用日期时间控件，不要求写提示词。

### 提醒

每两秒用当前真实时间查询到期任务，不能仅依靠内存倒计时。启动和睡眠恢复后自然补检；应用退出期间错过的任务在下次启动时显示。一次呈现最多 20 个，分批处理大量逾期任务。

提醒成功建立窗口后写入已呈现标记，以防常规轮询反复打扰；进程重启重新呈现仍未完成、未延期的到期任务。Windows 勿扰模式可能屏蔽托盘消息，但应用内提醒保留。系统崩溃与显示、写库之间的严格“恰好一次”不作保证；优先避免永久漏提醒。

### 设置与宠物

设置集中管理服务地址、模型、密钥、启动设置及宠物图片。默认 Key 仅保存在当前进程内；0.6 可选使用当前 Windows 用户的DPAPI加密文件记住，不存入JSON。开机启动通过独立按钮显式应用。图片复制后原文件删除不影响宠物；首版不去背景、不生成骨骼，不把图片摆动包装为 Live2D 或 3D。详细行为及验证边界见 [Windows设置](WINDOWS_SETTINGS.md)。

## 3. 架构

```text
Qt UI（主窗口、草稿、提醒窗、宠物）
  ├─ AssistantWorker → 兼容模型服务 / 本地有限规则
  ├─ TaskStore → SQLite
  ├─ QTimer → 到期查询 → 提醒呈现
  └─ Platform adapter → 数据目录 / 托盘通知
```

采用 Python >=3.10、PyQt5。业务与数据模块只依赖 Python 标准库；网络使用标准库 urllib，协议独立于模型厂商 SDK。通过依赖注入的时间参数测试提醒逻辑。UI 层持有数据库连接；工作线程只读取配置快照和消息快照，不接触 SQLite 或控件。

目录：`desktop_pet/core.py` 管理任务、会话、迁移、时间和协议；`assistant.py` 管理请求及离线规则；`platforms.py` 管理平台路径、通知；`app.py` 管理主窗口和请求状态。`ui/common.py` 放置日期控件与任务编辑对话框；`ui/tasks.py` 放置待办页界面方法；`ui/draft_card.py` 是通过信号通知保存/移除的独立草稿组件。初期不搬运旧项目聊天单体文件或大规模插件系统。

## 4. 数据设计

数据路径：Windows `%LOCALAPPDATA%/DesktopPet`；macOS `~/Library/Application Support/DesktopPet`；其他系统 `~/.local/share/desktop-pet`。开发可设置 `DESKTOP_PET_DATA_DIR` 隔离测试。数据库与图片不存进源码。

`tasks`：id（UUID）、title、due_at（UTC ISO 8601）、status（pending/done）、notified_at、created_at。输入和显示使用系统本地时区，落库统一 UTC。时区按操作系统当前设置处理，首版不支持单任务指定其他时区。

`sessions`：id、title、input_text、updated_at。记录会话名称、未发送输入和排序时间。会话新建及重命名独立于模型请求。当前不提供会话删除或归档。

`messages`：id、role、content、created_at、session_id。所有历史本地保存，每次请求只带原会话最近20条并限制单条长度，没有语义记忆和自动摘要。`settings.json` 只存 base_url、model、pet_image、active_session、stream、remember_key。密钥可选存为独立的DPAPI密文，绑定服务地址。

`drafts`：id、title、due_at、created_at、session_id。草稿随标题和时间修改持久化，允许空标题/过期时间暂存；确认时严格校验，并在同一事务中新增任务、移除草稿，防止重复保存。重启恢复所属会话的待确认卡片，过期草稿需要修改时间后保存。已确认任务归入全局待办列表。

数据库 schema version 为4；版本1/2/3升级前通过 SQLite backup API 建立带旧版本和唯一后缀的 `.bak`。在事务中补充草稿表、会话表、会话索引及重复字段，旧消息和草稿归入“默认对话”；旧任务默认不重复，保留任务及消息。较新未知版本拒绝打开，不能删除用户数据库重新建表。

0.5 任务增加 repeat_rule（none/daily/weekdays/weekly）、scheduled_at（原计划及固定UTC偏移）、next_id（已生成下一次）；草稿增加 repeat_rule。完成时在事务中生成唯一未来实例，延期不改原计划。列表支持本地日期筛选。详细语义、节假日/夏令时限制和验收见 [重复待办设计](REPEATING_TASKS.md)。

请求失败或主动停止后提供显式重试按钮，使用原请求的消息快照和最新保存的模型配置，不重复插入用户消息；新消息发送后清除该会话上次重试入口。正常回复的重新生成暂未实现。

## 5. 模型协议与约束

请求：`POST {base_url}/chat/completions`，base_url 为兼容 API 根地址（如供应商提供的 `/v1` 路径）。使用 messages、model，默认 stream=true；设置页可关闭流式。不假定所有服务支持 JSON response_format 或工具调用；若服务对流式请求直接返回普通 JSON，也能读取。

流式传输使用 SSE：逐行解析 data 事件，合并 delta.content；支持注释、空 choices 用量事件、UTF-8 和多行 data。要求收到 `[DONE]` 完成标记，提前断流、length/content_filter、超大事件或错误格式均不生成任务草稿。总响应上限2MB，单行上限256KB。服务没有标准完成标记时可关闭流式。不会在400错误后自动重新发送，以避免重复计费。

生成过程只展示 envelope 中第一个 reply 字段的文字，逐步解码转义字符并隐藏 tasks 原始JSON。要求模型将 reply 放在 tasks 之前；不符合时可能在最终完整回复才显示。普通非JSON文本允许预览，但仍无任务操作权限。界面最多约每60ms刷新一次预览。完整回复才进入历史和草稿；停止或断流的半截文本不持久化。

停止通过线程安全 Event 协作完成，主线程即时隐藏预览并忽略后续分片/结果，禁止强制终止QThread。工作线程在连接打开后、每次读取前后、最终返回前检查取消。阻塞中的网络读取可能等待约45秒超时，释放前不启动第二个请求；这不保证服务端立即停止生成或计费。退出时设置取消标记，等finished信号后关闭数据库和应用，不在线程存活时销毁其对象。

系统消息每次提供当前本地日期时间、时区偏移与规则。回复协议：

```json
{"reply":"我整理了一个待办，请核对时间后保存。","tasks":[{"title":"交报告","due_at":"2026-10-27T15:00:00+08:00"}]}
```

模型输出只当不可信数据处理。普通文本仍可展示，但不自动创建任务。校验对象、字段类型、长度、任务数量、ISO 时间和时区；无效建议显示原因。保存动作再次检查未来时间，避免长时间停留后把过期草稿保存。模型没有创建任务或触发系统操作的直接权限。

API Key 通过 Authorization 请求头发送到用户填写的服务；仅允许 HTTPS，开发用 localhost/127.0.0.1/::1 可使用 HTTP。禁止凭据嵌入 URL、查询参数及重定向转发密钥。超时 45 秒；无自动重试以避免重复计费。接入其他厂商先使用其兼容地址，专有协议以后扩展。

## 6. macOS 兼容边界

业务核心禁止 winreg、ctypes.windll 和 win32 依赖。数据目录、通知统一经过 platforms.py；Windows DPAPI和登录启动分别隔离在secure_storage.py、startup.py，其他平台禁用对应开关，未来实现Keychain和登录项适配。置顶透明窗口暂使用 Qt 标准属性。macOS 仍需单独验证 Apple Silicon 依赖、透明窗口、Spaces/全屏行为、托盘和通知权限，不能因接口存在就声称已经支持。

## 7. 质量与发布

核心测试覆盖：带时区输入、拒绝无时区和过去时间、任务完成/延期/重启恢复、重复呈现标记、错误 AI 协议、禁止不安全服务地址。UI 冒烟检查验证控件创建、无边框宠物与关键流程；真实 Windows 通知、休眠恢复及真实供应商联调需要人工或桌面环境验收。

## 0.8 今日规划

聊天页增加“今日规划”。只读快照从全部未完成待办生成，不受列表搜索或筛选影响；按当前本地日期区分逾期、今天稍后、未来日期。已完成、已删除及未确认草稿不参与。当前时间到期的事项归入逾期。快照最多展开30条，优先保留今天稍后的事项，其余名额展示最早逾期事项；精确显示总数及省略数。未来日期只提供数量，不展开标题。

确认对话框显示将使用的完整快照。已配置模型时明确显示待办标题、时间及本会话最近消息会发送到所配置的服务；未配置模型时仅在本地整理。确认后的快照以用户消息存入当前会话，不覆盖未发送输入。取消不增加消息、不发请求。重试复用原请求快照，重新点击规划才读取最新任务。

模型被要求只给文字顺序建议，不虚构工时或优先级，不重复创建任务；若仍返回任务建议，沿用原有草稿校验及人工确认流程。任何规划均不自动延期、完成或改写现有任务。未配置模型时明确标注“本地整理，未调用模型”，仅按提醒时间列清单，不将排序描述为智能优化。工作线程及会话切换沿用原隔离机制。没有模型时的普通聊天仍使用原本地规则模式。

## 0.9 生成另一版

聊天页增加“生成另一版”，仅在已配置模型、当前没有请求运行、最后一条用户消息已获回复时可用。不是失败重试的替代入口；最新问题尚未回复时继续使用已有的失败/停止重试入口。

重新生成采用新会话：事务中创建“另一版 · 原会话名”，复制截至最后一条用户消息的最近20条上下文，排除该问题之后的旧回复与保存草稿等反馈。原会话、未发送输入、任务及草稿保持原样；不会把原草稿复制到新会话。新会话独立持久化，重新启动后仍可查看。

新会话复用原请求生命周期，支持流式预览、停止、失败重试和切换会话隔离。失败或停止后，新会话保留问题以供本次运行重试。生成成功后仍按原规则将模型任务建议展示为新会话草稿，用户需要自行核对并确认；重新生成不自动创建待办，也不自动撤销原会话已经保存的任务。不承诺供应商每次都返回不同内容。今日规划的另一版使用原问题中的快照，需要更新快照时应重新点击今日规划。

## 0.10 本地背景移除

纯色背景移除使用边缘连通颜色填充，不是人物/动物分割模型。默认背景色由角落不透明像素的主色桶估计，允许手动调整。RGBA数据以独立副本处理，保持未移除区域的RGB和透明度。仅移除连到图像边界的颜色区域；封闭在主体内的同色细节不受影响，但主体边缘与背景颜色相近时仍可能误删。暂无羽化与发丝级边缘处理。

原图最多1600万像素；处理图最长边1024像素，避免大图导致高内存和耗时。模型服务不会收到图片，也不会下载模型或新增依赖。界面先预览，再应用；修改参数后必须重新预览。完全透明结果禁止应用。处理线程支持取消，完成前不销毁窗口及线程。

结果写入新的PNG文件，配置成功原子保存后才切换宠物；失败回退。新增配置字段pet_image_original保存去背景前路径，连续处理不覆盖最初原图。恢复原图后清除此字段；重新上传或恢复默认也清除。生成的旧资产暂时保留在应用数据目录，不自动清理用户图片。

## 0.11 动作序列

设置页提供待机、点击、提醒三类动作。用户为每个动作选择2～24张本地图片，文件名按数字自然排序（1、2、10）。帧率可选5～20帧/秒。每帧输入不超过100万像素，整组合计16 MB以内。导入后统一缩放到256像素边界并转为PNG，复制至应用数据目录animations下独立随机目录；不执行素材附带代码，不解析压缩包。

配置字段pet_animations按动作保存帧路径及帧率，恢复时只接受animations目录内的有效小尺寸帧。单个动作任一帧缺失或损坏则放弃该动作，回退待机或静态形象，不影响聊天和提醒。旧导入素材暂保留，移除动作只清除配置引用。

待机循环，点击和提醒播放一次后回待机；无待机序列时回静态图片或默认宠物。提醒播放时点击不能打断；多条同时到期的提醒共享同一种提醒动作。暂停动画同时暂停动作序列，文本提醒继续；恢复后继续计时。动作以单调时钟推进，定时器40毫秒刷新，繁忙时可能跳帧。事件动作在隐藏时同样推进，显示时呈现当前进度。

动作形象优先于静态形象。上传/去背景仍编辑静态备用图片；要显示它应移除待机动作。恢复默认宠物会清除所有动作配置。素材仅为用户导入，不会从单图自动生成动作，不等同于Live2D或3D。

## 0.12 从单图生成基础动作

从当前静态宠物图片生成三组本地动作：待机呼吸（轻微缩放）、点击弹跳（位移与压缩）、提醒摇摆（旋转）。保持原图片内容和透明度，不调用网络、视觉模型或图像生成服务，不识别人物/动物关节，也不生成新视角、肢体动作或表情。

每组16帧、256×256透明画布、10帧/秒。原图等比缩放至172像素边界并置于安全区域，避免最大动作幅度时裁切。可调幅度0～100，调整后延迟120毫秒刷新预览；三类动作可分别预览，预览循环播放便于检查。实际点击/提醒仍按动作播放器规则仅播放一次。

应用前不保存新素材或改写配置。确认后另存独立目录并一次性替换三类动作，原静态图片不动。配置pet_animation_backup保存上一组动作引用，可跨重启撤销最近一次生成；连续生成只保留一步撤销。手动导入/移除动作或恢复默认会清除此撤销记录。保存失败保持原形象及动作并清理本次新素材。已有动作素材仍保留，不自动删除。

## 0.13 Windows 构建准备

增加固定版本PyInstaller的独立构建流程，以launch.py为入口生成windowed/onedir文件夹版。唯一时间戳输出避免覆盖旧产物；构建后执行EXE离屏自检，通过后收集许可证、文件哈希清单及ZIP。不会复制用户数据或旧项目资源。

StartupManager区分源码与frozen模式，打包程序直接以EXE --background登录启动，不依赖launch.py。启动配置仍仅由用户显式应用。主窗口标题包含版本号。

实现了专用 --version 和 --smoke-test 报告入口；后者仅使用离屏Qt、内存数据库和合成图片，不接触真实设置或密钥。免安装文件夹版尚无签名、安装器或自动更新。

本次构建依赖下载被环境权限限制，提权审批服务404 model_not_found，未实际安装PyInstaller或生成EXE。源码自检通过不代表打包后可运行，仍需补齐真实产物验收。
