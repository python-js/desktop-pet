# Desktop Pet 产品与技术设计

当前实现基线：0.31.0（2026-11-11）。目标平台为 Windows 10/11 x64；macOS 尚未完成适配验证。本文描述当前方案，历史实现细节与分阶段回归见 [实施记录](IMPLEMENTATION.md) 和 [验证记录](VALIDATION.md)。Web 界面与 Python 后端之间的方法、事件及数据格式见 [BRIDGE_API.md](BRIDGE_API.md)。

## 产品目标

Desktop Pet 是一个驻留 Windows 桌面的个人事务助手。用户可以在主窗口或桌宠入口中聊天、创建和管理待办；应用保存在本地的数据由 SQLite 管理，桌宠和提醒窗口在程序运行时提示用户。

首版覆盖首页、任务、对话、设置和独立宠物窗。当前宠物窗由 Qt 宿主管理，2D 图片由本地绘制；可选用本地 QtWebEngine 渲染的内置 3D 哈士奇。上传图片显示为 2D 宠物形象，并不会自动生成人物/动物模型、骨骼动画或 Live2D。图片去背景仅支持有限的本地纯色边缘处理。

### 用户能力

- 连接用户配置的 OpenAI Chat Completions 兼容服务，支持多会话、Markdown、SSE 流式回复、停止、重试和重新生成。用户自行提供服务地址、模型和 API Key。
- 使用自然语言创建、修改、完成和删除待办。任务信息缺少必要时间时追问；通过应用校验后直接落库执行，不要求再点保存。多义对象由本地候选与序号处理。
- 重复规则支持一次、每天、周一至周五和每周。每月或自定义间隔未实现。完成重复任务会生成下一次；到期提醒有限次，用户可延期、完成、免打扰当日或顺延。
- 今日规划仅读取任务快照并请求模型给出文字建议，不自动改写任务。联网搜索和本地文档知识库可按设置启用，相关查询或检索片段可能发送给模型。
- 可选钉钉机器人按任务推送提醒。Windows 用户可用 DPAPI 记住模型、Tavily 与钉钉凭据。
- 明暗主题、布局密度、免打扰、提前提醒、声音、自动顺延、登录启动、数据导出和清空均由设置管理。

## 用户流程

聊天界面提交自然语言后，模型返回 Markdown 文字和末尾结构化 `tasks` 块。Python 校验标题、时区时间、重复规则及操作目标，再直接执行允许的任务操作并将回执写回对话，不要求用户再次保存。对同一未完成事项的操作必须引用当前任务清单中的 ID；同标题匹配多个项目时，应用暂停操作并让用户选择。只有事项或必要时间不完整时才追问。没有模型时，仅本地规则可以识别有限的定时提醒句式，不提供通用聊天或待办修改能力。

创建任务要求标题和有效的未来提醒时间。写库由 SQLite 事务执行；更新、完成和删除都由应用执行并生成回执。软删除可撤销最近一次删除。数据导出不包含设置或密钥；清空数据先生成数据库备份。

今日规划先在本地生成不含密钥的快照，向用户展示后才提交模型请求。规划模型不得创建或改动待办。停止请求会丢弃未完成的生成；如果网络读正阻塞，取消要等读取返回或超时，不能保证上游服务立即停止或停止计费。

## 架构

```text
React + TypeScript + Vite + HeroUI + Tailwind
        │  本地 file:// WebView，通过 QWebChannel / JSON 信封
        ▼
PySide6 壳 + BridgeHost + bridge_modules
        ├── TaskStore → SQLite / 迁移备份 / 待办与事件
        ├── AssistantWorker → OpenAI 兼容服务 / SSE
        ├── KnowledgeBase / Tavily / 钉钉客户端
        ├── SecretStore / Windows DPAPI / StartupManager
        └── Qt 主窗口 / 托盘 / 宠物窗 / 提醒弹窗
```

主窗口采用 `web/` 唯一界面，不再保留 Qt 页面回退。Web 与 Python 之间只有注册白名单的 JSON 信封桥，不启动本地 HTTP 服务。`desktop_pet/bridge.py` 负责模块路由、信封、作业和事件缓冲；`bridge_modules/` 负责界面 API 参数转换，业务校验和持久化留在 Python 后端。`desktop_pet/app.py` 管理线程、提醒调度与 Qt 生命周期；`core.py` 管理 SQLite 任务、会话和消息。

同步桥调用必须短小，网络和文件导入等操作通过后台作业执行。`TaskStore` 的 SQLite 连接仅由主线程使用；模型线程得到配置和消息快照，不触碰 UI、桥对象或数据库。Worker 结果经 Qt 信号回到主线程后写入数据库，再通过桥事件更新 React 状态。

React 使用 Vite 单文件构建，运行页面不通过 HTTP 拉取模块。QWebChannel JavaScript 从 Qt 资源加载。3D 场景由 `web/public/pet3d/` 提供本地页面、three.js 与模型；透明窗口输入事件和 2D/3D 切换仍由 Qt 宿主管理。

## 数据、安全与提醒

数据默认位于 `%LOCALAPPDATA%\DesktopPet`：`desktop-pet.sqlite3`、`settings.json`、密钥密文、图片与知识库。Schema 当前为 7，升级时先生成唯一命名的 SQLite 备份；不接受高于当前版本的数据库。导出只包含任务、任务事件、会话、消息和草稿表，不包含设置及密钥。任何发行包都不应带入用户数据目录。

API Key、Tavily Key、钉钉 Webhook 和加签密钥不会传到 React 页面。选中“记住”后，Windows 使用当前账户 DPAPI 保护密文；其余偏好保存在 settings.json。连接要求使用 HTTPS；仅 localhost 可用 HTTP；请求不跟随重定向，不在日志中写入认证头。模型输出被视为不可信数据，任务 ID、时间、枚举和文本长度都需本地校验。

应用在运行时每 2 秒检查提醒；免打扰时段、提前提示、重复任务和提醒次数上限由后端统一判定。隐藏到托盘时仍运行；完全退出、关机或睡眠期间不会准时弹出，启动后会补检尚未处理的逾期任务。因此它不是系统闹钟，不能承载必须可靠送达的关键提醒。

## 打包和未覆盖范围

Windows 发行使用 PyInstaller onedir。构建先运行 `web/npm ci` 和 Vite 构建，再检查包内 Web/3D 资源，执行隔离数据的 EXE 自检，并生成 ZIP、许可证和 SHA256 清单。详细命令、当前构建差异及发行边界见 [WINDOWS_BUILD.md](WINDOWS_BUILD.md)。

当前缺口包括图片生成 2D/3D 角色、Live2D、macOS、安装器、代码签名及自动更新。Win10、不同 DPI、双屏/跨屏、休眠恢复和干净机器首次运行仍需目标机验收。验证记录列出已跑的测试、桌面检查及其时间点；版本或文档变更不应冒充重新执行过这些检查。
