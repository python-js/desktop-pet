# Word 与 PDF 切片流程

本文说明资料库导入 Word（`.docx`）和 PDF 时，文字怎么切、图片怎么处理，以及切完之后如何被检索并出现在回答里。实现集中在 `desktop_pet/knowledge.py`。

测评 Word（导入测评、识图、评分）不走这条链路，图片存在 `assessment_assets`，不进资料库全文索引。

## 1. 共用边界

| 项目 | 值 | 作用 |
| --- | --- | --- |
| 单文件上限 | 30 MB | 超过则拒绝导入 |
| 抽取正文上限 | 150 万字 | 超出后停止继续读 |
| 检索块目标长度 | 600 字 | 段落尽量整段装入 |
| 无标点长句重叠 | 80 字 | 只在按字窗口兜底时使用 |
| Wiki 分段 | 6000 字，最多 4 段，重叠 200 字 | 交给模型整理笔记，不按标题切开 |
| 检索条数 | 最多 4 条，同一文档最多 2 条 | 回答时带入的资料 |
| 单条上下文 | 先取 800 字，全部资料合计约 2600 字 | 送给回答模型的原文 |

文件内容没变时再次导入会跳过。界面上的「重建所选」只强制重建当前点中的那一份，不扫全部资料。原文件被移动或删除时，这一份无法重建。

入库后会留下三样东西：

- `files/`：原始文件副本
- `pages` 与全文索引：检索块，分 `raw`（原文）和 `wiki`（模型整理的笔记）
- `wiki/{文档id}.md`：整篇 Wiki 的 Markdown

只有 PDF 配图会写入 `assets/` 和 `doc_images`。

## 2. 共用切片规则

Word 和 PDF 的正文最后都进 `chunk_text`。规则按下面的顺序执行。

1. `\f` 是硬边界。Word 在题号或标题样式前插入它。边界两侧的文字不会并进同一块。
2. 空行分成段落。连续空行收成一个空行。
3. 单独成行、不超过 40 字、结尾不是 `。！？；.!?;`，并且符合下面任一种写法的行，视为标题，从这里新开一块，后面的正文跟在标题后面：
   - Markdown `#` 到 `###`
   - `第一章`、`第三节`、`第二部分` 这类「第…章/节/篇/部分/部」
   - `一、`、`（一）`
   - `1.`、`1、`、`1.1`、`1.1.1`
4. 段落不超过 600 字时，整段装入当前块；装不下就先结束当前块。
5. 一段超过 600 字时，先按 `。！？；!?` 断句。英文句号只在后面是空白时才断开，所以 `1.1`、`3.14` 不会被拆开。句子整句装入，直到再装就超过 600 字。
6. 一整句没有上述标点、又长过 600 字时，才按 600 字窗口切开，相邻窗口重叠 80 字。

Wiki 整理刻意关闭标题断开，否则前 4 段会被切成很多小标题，后面的章节进不了笔记。

## 3. Word

解析使用 `python-docx`，按文档正文的实际顺序走段落和表格，不按样式把标题提前抽走。

### 3.1 文字

- 普通段落原文保留。
- 表格按行读，单元格用 ` | ` 连接。空单元格丢掉。
- 段落文字匹配 `1.`、`1、`、`第一部分`，或样式名以 `Heading`、`Title`、`标题` 开头时，在这段前面插入 `\f`。切片时从这里断开，避免上一节的内容混进下一节。
- 断开之后仍走第 2 节的 600 字规则。

### 3.2 图片

Word 资料库**不抽出图片文件**，也不做识图。

- 段落里数到几张内嵌图，就在该段落后面加一行：`[包含 N 张图片，图片文字尚未识别]`。
- 表格行里有图时，把同样的占位接在这一行末尾。
- 占位文字会进入检索块，所以能搜到「这里有图」，但回答里不会出现原图。
- 页眉、页脚、文本框里的图不在这次扫描范围内。

## 4. PDF

解析使用 `pypdf`。按页读取，读到的正文字数超过 150 万即停止。加密或损坏的文件整份失败。

### 4.1 文字

每一页先 `extract_text`，再还原成标题和段落：

- 空行结束上一段。
- 命中第 2 节标题规则的行单独成段。
- 同一段里被 PDF 换行拆开的行会拼回去：相邻汉字直接相连；上一行以 `-` 结尾则去掉连字符再拼接；其余情况中间加空格。

页与页之间不再插入 `\f`，所以页边界本身不会强制切开。标题和空行仍然会切开。

### 4.2 图片

配图在读每一页时另抽，依赖 Pillow。未安装 Pillow 时，导入直接失败并提示「未安装图片解析组件」，不会再把配图悄悄丢掉。

抽出后按下面规则过滤：

| 规则 | 结果 |
| --- | --- |
| 宽或高小于 80 像素 | 丢掉，用来跳过小图标 |
| 小于 8 KB | 丢掉 |
| 内容哈希相同 | 只保留第一次出现 |
| 一份 PDF 最多 40 张 | 超出的不再保存 |
| 已经配置模型时，前 24 张做识图 | 每张说明最多 200 字 |
| JPEG、PNG、WebP、GIF | 保留原字节 |
| 其他可解码格式（如 JPEG2000） | 转成 PNG 再保存 |

编号是图片内容的 SHA-256 前 24 位。文件放在 `assets/{编号}.jpg`（或对应扩展名）。同一张图被多份资料用到时共用这一个文件；删除资料时，没有别的资料引用才删文件。

识图在导入时做一次，使用当前偏好里的视觉模型，提示词要求只用一两句说明图里可见的界面和操作。某一张识图失败时，这张图仍保存，只是没有说明。没配置模型时也保存原图，只是搜不到图里的字。

矢量图、绘制的箭头、转曲文字抽不出来。整页扫描件会被当成一张大图；有文字层的页仍以文字层为准。

pypdf 不能保证图夹在哪一句中间。图跟在**该页**文字切出来的每一块末尾，格式是单独一段：

```text
[[img:编号]] 右上角是设置按钮。
```

没有说明时只留 `[[img:编号]]`。因此同一页上任意一块被检索到，这块都带得走该页的图。图不会自动跟到下一页。

### 4.3 PDF 切片顺序

1. 按页还原标题和段落。
2. 过滤并去重图片，需要时写说明。
3. 对该页正文执行第 2 节的 `chunk_text`。
4. 把该页的图片行追加到这一页的每一块后面。某一页只有图、没有文字时，图片行自己成为一块。
5. 各页的块按页序接成这份 PDF 的原文索引。

送给 Wiki 的正文是「每页文字 + 该页图片行只出现一次」，再按 6000 字取前 4 段，不按标题拆开。

## 5. 从导入到回答

```text
选择文件或「重建所选」
        │
        ▼
解析文字，PDF 同时抽图、识图
        │
        ▼
切成检索块；已配置模型时再整理最多 4 段 Wiki
        │
        ▼
写入 pages / 全文索引；PDF 图片写入 assets
        │
        ▼
用户提问 → 全文检索命中原文或 Wiki
        │
        ▼
命中的文字和 [[img:编号]] 交给回答模型
        │
        ▼
模型把编号单独放在对应步骤下一行；一个都没写时，把本次命中的图补在回答末尾，最多 4 张
        │
        ▼
聊天气泡把 [[img:编号]] 换成本地原图，点击可放大
```

检索先用 FTS5（trigram）和 bm25，不够再按关键词扫，最后才用整句模糊匹配。预览片段大约 300 字，并尽量落在命中的词附近；回答使用的是完整检索块，不是预览片段。

回答模型只看到图片编号和说明，不会在每次提问时重新接收原图。界面根据编号向 `knowledge.image` 读取 `assets` 里的文件。编号必须是已入库的 16 到 64 位十六进制，并且文件必须位于 `assets` 目录内。

模型被要求原样复制编号，不能编造。它只要写进了任意一个 `[[img:`，程序就不再往末尾补图。待办操作会改写整段回复，这种回复不附带配图。

## 6. 两种文件的差别

| | Word | PDF |
| --- | --- | --- |
| 正文顺序 | 段落、表格按文档顺序 | 按页，页内再还原段落 |
| 标题断开 | 题号和标题样式前插入 `\f`，硬切开 | 识别到的标题新开一块，页边界不硬切 |
| 图片文件 | 不保存 | 保存到 `assets`，最多 40 张 |
| 图片文字 | 只留「尚未识别」占位 | 导入时给前 24 张写说明，说明可检索 |
| 回答里的图 | 不显示原图 | 步骤下显示原图，没插上则附在末尾 |

已经导入的 PDF 不会自动补图。要配图，需要在资料清单里点中该文件，再点「重建所选」。
