# Desktop Pet

Windows 首版开发原型：聊天、待办、到期提醒、上传图片宠物。独立于原 `opendoro`，不会读取其模型配置或个人记录。macOS 尚未验证。

0.2 新增：任务搜索与已完成历史、恢复待办、删除与撤销、失败请求重试、未确认草稿自动保存和重启恢复。更新代码后需从托盘退出旧实例，再重新运行。首次升级会自动备份旧数据库，不清空已有记录。

0.3 新增：多会话、新对话自动命名及手动重命名；每个会话分别保存消息、未发送输入和待确认草稿。回复期间可切换会话，结果始终写回原会话。目前一次处理一个请求，其他会话可浏览和编辑；已确认的待办在统一任务列表管理。旧聊天和草稿迁入“默认对话”，升级前备份数据库。

## 启动

需要 Python 3.10+。在本目录执行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m desktop_pet
```

安装完成后也可运行 `start.ps1`。尚未提供安装包。

## 体验顺序

1. 在聊天页输入“明天15:00提醒我交报告”。未配置模型时是有限的本地规则识别。
2. 检查草稿标题和具体时间，点击“确认保存”；在待办页编辑、完成或延期。
3. 新建几分钟后的任务测试提醒。关闭主窗口但保留托盘；到点显示提醒窗、宠物气泡及系统允许的托盘消息。
4. 设置页填写供应商提供的兼容 API 根地址、模型和自己的 API Key，再点击保存。Key 默认只保留在当前进程中，也可选用当前 Windows 用户加密记住；请求会把近期聊天发送给所配置的供应商。
5. 可上传透明 PNG 作为宠物。图片只在本地使用；当前是基础浮动动画，尚无图片生成、自动去背景或 Live2D。右键菜单可切换到内置 3D 形象，3D 模式需要安装 `PyQtWebEngine`，未安装时自动回退到 2D。

完全退出、关机或睡眠期间不即时提醒；下次运行/恢复补检。请勿用本原型承载关键提醒。0.4 支持 SSE 流式回复和停止当前请求。设置页可关闭流式，兼容不支持该协议的服务。

生成中展示回复文字，完整回复通过校验后才出现任务草稿。停止会丢弃不完整回复及其建议；若连接正阻塞等待，需等读取返回或超时后才能发送下一条。网络阻塞通常等待最多约45秒，停止展示不保证供应商立即停止生成或计费。失败/停止后的重试入口仅在本次运行中保留。请求期间退出，会停止并等待线程结束再自动关闭。无需新增依赖或数据库升级。

## 测试

```powershell
python -m unittest discover -s tests -v
```

测试只使用临时数据库和模拟服务，不产生真实 API 费用。

### 宠物互动（0.7）

单击宠物显示反馈，双击打开聊天，拖动后记住位置。右键可暂停/恢复浮动动画或重置位置。宠物找不到时，在系统托盘菜单选择“找回宠物”。位置和动画状态会在下次启动恢复；移除屏幕时自动将宠物移回可用屏幕。

### 今日规划（0.8）

在聊天页点击“今日规划”，先预览现有待办，再确认生成。未配置模型时仅生成本地清单；配置模型后，会把预览中的待办标题和时间及本对话最近消息发送给所配置的服务，请在预览中核对。清单区分逾期、今天稍后及未来日期数量，最多展开30条并显示省略数。规划不会覆盖输入框内容，也不会自动修改、延期或完成任务。模型建议的处理顺序不代表提醒时间已变更。

### 生成另一版（0.9）

配置模型并获得回复后，可点击聊天页的“生成另一版”。应用会在新对话中重新回答最后一个已回复的问题，原对话、输入和任务草稿保留。失败或停止后可在新对话重试；新任务建议仍需核对保存，不会自动重复创建待办。今日规划的另一版沿用原快照，想读取最新任务请重新点击“今日规划”。未配置模型时不启用此按钮。

### 纯色背景移除（0.10）

在设置页上传宠物图片后，点击“纯色背景移除”，选择背景颜色并调节容差，再点“预览去背景”。棋盘表示透明区域，检查主体是否完整后点击“应用到宠物”。不满意可取消；应用后可在设置页“恢复去背景前原图”。

此功能在本地处理，适合白底、绿底等纯色背景，不会上传图片或调用模型。处理结果最长边1024像素，原图保留；复杂照片、毛发、阴影和主体与背景同色的情况可能效果不佳，暂不支持自动人物/动物语义分割。

### 动作序列（0.11）

设置页“宠物动作”可选择待机、点击、提醒，为每个动作导入2～24张PNG/JPG/WebP图片。建议保持相同画布和主体位置，命名为1.png、2.png、3.png等，按数字排序播放。每帧不超过100万像素，整组16 MB以内；导入副本最长边256像素，可选5～20帧/秒。

待机循环，点击和到期提醒播放对应动作一次，然后回到待机；未导入的动作使用静态形象。可试播、移除此动作；暂停动画同时暂停动作播放。重启会恢复已导入动作。

动作优先于静态形象：如需显示上传或去背景后的静态图片，请先移除待机动作；“恢复默认宠物”会移除全部动作配置。此入口播放用户提供的动作帧；从单图生成基础动作见下节。

### 单图生成基础动作（0.12）

上传宠物图片后，在设置中点“单图生成基础动作”，即可预览呼吸、弹跳和摇摆三类动作，调节幅度后确认应用。建议使用透明背景图片，或先去除纯色背景。

应用会替换现有的待机、点击和提醒动作；可通过“撤销最近生成”恢复前一套动作，重启后也可撤销。手动导入/移除动作或恢复默认会清除这次撤销记录。预览取消不会改变当前形象，原静态图片一直保留。

此功能只对整张图片做本地缩放、位移和旋转，不生成新表情、关节动作或新视角，不调用模型，也不上传图片。角色级动作生成仍待后续实现。

### 宠物形象与自动动作（0.19）

“宠物形象”和“动作工作室”合并为一张卡片：默认形象与历史上传图片以缩略图并排展示，点击即可切换；上传新图自动加入历史，可单独移除。上传、切换、去背景或恢复原图后，本地自动生成待机、鼠标移入（小跳）、点击（跳跃）和提醒（摇摆）四类动作，不再需要手动导入与调参。旧版手动动作入口已停用但数据仍可加载。详细说明见docs/UI_DESIGN_SYSTEM.md。

0.19.1 修复动作帧透明留白导致宠物变小：动作帧按内容占比放大绘制，待机尺寸与原静态图一致，已在用的动作无需重新生成；内置默认形象也改为填满画布。

0.20 起桌宠只显示上传的原图（保留轻微上下浮动），不再自动生成或播放动作，避免动作帧反复缩放造成的模糊。启动时会移除旧的动作配置并清理animations/auto-*目录，旧手动导入目录保留；设置页图库的切换、去背景与删除不受影响。

0.20.1 桌宠气泡改为按内容自适应：宽度随最长一行收缩、高度随行数增长，底边固定停在宠物头顶上方；超过3行用省略号截断，悬停提示保留全文。

### Markdown 对话与流式占位（0.21）

模型回复改为 Markdown 正文，任务建议放在回复末尾的 tasks 代码块（JSON 数组）中，不再要求整条回复包成 JSON 信封；聊天页助手消息使用 Qt 原生 setMarkdown 渲染标题、列表、表格、引用与代码块，用户消息仍按纯文本显示。旧数据库里的 JSON 信封消息在加载时容错解码，模型写坏转义或嵌套信封也能还原成正文。流式输出不再使用独立预览面板，而是在历史中创建一条助手占位消息并原地更新，思考中转为正式答案时页面不再跳动。0.21.1 起发送消息时仍会跳到最新内容，但流式更新只在已接近底部时跟随，用户上滚查看历史不会再被每 60ms 拉回底部。

### 钉钉群通知（0.22）

到期待办可推送到钉钉自定义机器人（加签模式）。默认关闭：只有聊天中明确说“钉钉群通知/发到钉钉群”，或在待办编辑里勾选“同时发送到钉钉群”的任务，到期才推送；其他任务仍只做桌宠气泡、提醒卡和托盘消息。设置页新增“钉钉群通知”卡片，填写 Webhook 与加签密钥后可发送测试；两者由当前 Windows 用户通过 DPAPI 加密保存，不写入 settings.json。推送在后台线程执行，失败不阻塞本地提醒，只在状态栏和托盘提示，不自动重试。重复任务生成下一次时保留该标记。

### 对话内管理待办（0.23）

对话现在可以修改、完成和删除已有待办。每次请求会把最多 50 条未完成待办的 id、标题、本地时间、重复规则与逾期状态附在系统提示词中，模型必须逐字引用其中的 id；tasks 块新增 `action` 字段（`update`/`complete`/`delete`，缺省仍是创建），修改时只覆盖给出的字段，未给出的保持原值。本地规则模式不处理管理请求，会提示到待办页操作。

程序不信任模型的选择：id 必须存在于当前未完成列表，否则该条不写库；修改后的时间、重复和标题仍走原有校验；已逾期的待办只改标题或重复时会被拒绝，要求同时给出新时间。若目标标题存在多条未完成待办，程序不执行，而是列出带序号、时间和重复规则的候选，用户回复序号后在本地直接执行（不发起模型请求），回复其他内容则取消；选择状态按会话保存，应用重启后失效。修改回执显示“原 → 新”，完成重复待办会注明生成的下一次，删除可在待办页撤销最近一次。

### 提醒次数上限与延期（0.24）

同一未完成待办最多弹出 3 次提醒：启动补提醒、手动“10 分钟后”再次到期都计入次数。第 3 次提醒卡会提示“已提醒 3 次，关闭后将标记为延期，不再提醒”，并禁用“10 分钟后”。达到上限后任务仍留在未完成列表，首页逾期统计继续计入，但不再弹窗、气泡、托盘或推送钉钉；待办页与首页时间线显示“已延期”。双击修改提醒时间，或在已完成页恢复该任务，会清零次数并重新开始提醒。数据库升级到 schema 6，旧记录默认次数为 0。

0.24.1：侧栏移除“工作空间”小标题，导航项行高增至 40px、字号 15px、间距 8px，菜单整体更宽松。

### 3D 桌宠（0.25）

桌宠新增内置 3D 模式：由本地 three.js 渲染的低多边形狐狸（Khronos glTF 示例模型，带 Survey/Walk/Run 骨骼动画），窗口保持透明、无边框、置顶。右键菜单可在“切换到 3D 形象”和“切回 2D 形象”之间切换，2D 模式继续显示上传的图片。拖动、双击打开聊天、右键菜单、位置记忆与多屏找回在两种模式下一致；3D 窗口比 2D 高 80px，切换时保持底边位置不变。

3D 模式使用随程序打包的 three.js 与场景文件，不访问网络。需要新增依赖 `PyQtWebEngine`；若运行环境未安装或无法创建 WebEngine 视图，启动时自动回退到 2D，并在状态栏提示。上传新图片只影响 2D 模式。

0.26：3D 待机动画。狐狸会持续轻微呼吸、上下浮动，随机眨眼（约 2.6–5.4 秒一次），尾巴与气球按各自节奏缓慢摆动。右键“暂停动画/恢复动画”现在同时作用于 2D 和 3D；暂停状态写入设置，下次启动继续生效。动画在页面内由 `window.pet3d.setPaused()` 控制，暂停时停止渲染循环，不占用持续 GPU。（0.29 换成骨骼模型后，程序化模型与呼吸/眨眼/气球动作已移除。）

0.27：3D 鼠标互动。狐狸的眼睛会跟随桌面鼠标方向转动；单击宠物会小跳、甩尾并睁大眼睛；拖动时宠物轻微离地晃动，松手恢复。暂停动画时视线跟随一并停止。（0.29 起改为头部骨骼转向，单击播放 Run 动画并小跳。）

0.28：3D 偶尔巡逻。静止 20–40 秒后，狐狸会沿当前屏幕水平走 3–6 秒（约 45 像素/秒），到屏幕边缘自动掉头；鼠标移入、按下或暂停动画时立即停下。右键菜单可暂停/恢复走动，状态与位置会保存到下次启动。

0.29：换成 Khronos glTF 示例狐狸。用 GLTFLoader 加载内嵌的 Fox.glb（base64，避开 file:// 读取限制），复用其 Survey、Walk、Run 三段骨骼动画：待机循环 Survey，走动循环 Walk，单击播放一次 Run 后回到当前状态；鼠标方向通过头部骨骼转向体现，拖拽仍轻微离地晃动。相机改为 24° 视场、距离 10，模型高 2.1 个单位，走动的侧转收敛到约 0.62 弧度，避免长身体在 220px 窗口内被裁切。模型由 PixelMannen（CC0）制作、@tomkranis 绑定与动画（CC-BY 4.0），署名见 `desktop_pet/assets/pet3d/FOX_LICENSE.txt`。

0.30：狐狸换成 Quaternius 的哈士奇（CC0，来自 Poly Pizza）。GLB 内嵌为 `husky.glb.js`，复用其 Idle（待机循环）、Walk（走动循环）、Gallop_Jump（单击播放一次）三段动画；相机与交互不变，模型按高度缩放至 2.4 个单位，走动转向仍约 0.62 弧度。0.30.1 修正视线：哈士奇的耳朵挂在 Neck3 下，改转 Neck3 并用世界坐标的偏航/俯仰换算到父骨骼空间，整个头连同耳朵一起跟随鼠标，不再只有鼻子动。`fox.glb.js` 与 `FOX_LICENSE.txt` 保留作回退，署名见 `desktop_pet/assets/pet3d/HUSKY_LICENSE.txt`。
